# Kizn guidance for OMP

The Kizn provider for **Trailboss OMP Integration**. It receives canonical Kizn instruction changes over the existing authenticated native MCP connection and publishes them as passive model context without another model Kizn call. No Agent Mail, credential storage, second OAuth client, instruction polling, OMP core change, or persistent settings change.

## Activate

1. Configure the existing native MCP server under the exact name `kizn`, pointing to a Kizn API that advertises resource subscriptions and implements `kizn://instructions/{sessionHandle}`.
2. Install workspace dependencies with Bun. Link `packages/trailboss` and then this package with `omp plugin link`; both must be enabled. A disposable process can instead load both `packages/trailboss/src/index.ts` and this package's entry point with `-e`.
3. Start a new OMP process, or use the host's extension reload mechanism if it emits a fresh `session_start`. A process started with extensions disabled will not activate this package merely because it was linked.

The extension owns a private `start_session` call through `MCPManager.instance().getConnection("kizn").transport`. It discovers every fetch/push remote URL from `git -C <actual conversation cwd> remote -v`. A non-repository directory uses an empty repository scope; unexpected Git errors fail visibly rather than silently changing scope. This independent subscription session supports Eval-only tool use and activation in conversations whose models already have their own Kizn sessions. Its private handle is never supplied as the model's write handle. Models retain their existing handle or deliberately call `start_session` if needed. The canonical version hash identifies instructions and scope, not the session handle.

## Delivery and lifecycle

- Initial and changed snapshots are published to the Trailboss integration through `trailboss:context:publish`, with synchronous acceptance. This never calls `sendMessage`, prompts the agent, or changes its status. An idle agent stays idle; an active agent receives current instructions at its next outgoing model-context boundary without interrupting tools. Real work retains normal completion signals.
- Reads and subscriptions use the same native transport/auth/session as configured Kizn. Native `startSSEListener()` runs before subscribing, including recovery from a GET that returned 405 before the API supported subscriptions. Because that native method can resolve without an established stream, activation waits up to ten seconds for Kizn's initial URI invalidation before reading the canonical snapshot. Missing delivery produces a visible stale-guidance warning; a later matching notification can recover the already acknowledged subscription. This does not poll, automatically retry failed RPCs, or change native request timeout settings.
- Native manager connection-status events create a fresh private subscription session and catch up after reconnect, including when the previous handle expired or was revoked. In-flight invalidations coalesce; an already-received invalidation survives a failed read, but a failed RPC alone does not start a retry. No instruction version starts an idle turn. A response from a superseded session/connection generation cannot publish context.
- Switches, forks and tree changes create a fresh owned session with the current repository scope. A same-session `/move` also rebinds from captured cwd identity at the next agent-start or outgoing-context boundary; a mutable host context cannot keep the old repository active. Shutdown aborts owned work, removes connection listeners and unsubscribes without closing the shared transport. No private subscription binding is persisted to disk.
- Current instructions are republished at agent-start boundaries. The context hook also restores the complete current scope/version snapshot when compaction removes it or a repository rebind publishes after the shared context hook already ran; inherited or superseded snapshots are removed. Rules, Memories, Concepts and evidence retain their original owner/kind authority; delivery does not claim that on-demand bodies were read or automatically acknowledge/retry a write.

An accepted URI invalidation immediately marks retained instructions stale while the canonical replacement read is pending. A successful read, including one with the same version, clears that status. Actual failures also produce a generic UI warning or stderr message. The model-context stale/unavailable status contains no tokens, handles, owner data or snapshots; it does not misreport an ordinary pending refresh as a failed subscription. Reconnect creates a new private session; reload or an explicit refresh is also available before writing. There is no silent success or retry loop.

Explicitly disabling the native Kizn server marks retained guidance stale at the next outgoing model-context boundary, even though that host action does not emit a connection-status event. The last policy snapshot is not discarded.

## Host compatibility

The package peers with OMP `^18.10.4`. Historical authenticated push verification with installed OMP 18.11.0 established native-manager reuse, committed external-change notification, canonical-resource refresh and dedicated-listener cleanup. That older implementation woke an idle model; this is no longer the delivery contract. The Trailboss package's isolated real-SDK harness verifies the passive path without network credentials. Installed processes must reload the changed extensions before receiving the new behavior; no claim is made that all running agents have reloaded.

The native package exports `@oh-my-pi/pi-coding-agent/mcp/manager` via its `./mcp/*` export. Required APIs are `MCPManager.instance`, `getConnection`, `addConnectionStatusListener`, transport `request`, HTTP `startSSEListener`, extension `mcp_notification`, `before_agent_start`, `context`, session lifecycle events, and the public extension event bus. Trailboss OMP Integration must accept publications on that bus. Missing capability is reported rather than silently claiming successful delivery; no private-field inspection, replacement transport, or OMP core patch is used.

`mcp.notifications` gates OMP's generic automatic resource subscriptions/context queue, not raw notification fanout to extensions. This package subscribes only its owned canonical URI and consumes that raw native event, so it does not enable a global notification setting, subscribe to unrelated servers, or write installed configuration.

OMP currently negotiates MCP 2025-11-25. This package uses that actual legacy `resources/subscribe` + authenticated GET SSE flow. Kizn's modern 2026 `subscriptions/listen` endpoint is a separate supported server protocol, not a client fallback here. Native OMP owns reconnect/auth; this package does not close/reconfigure the shared connection. A fresh MCP authorization or server configuration requires the normal host reconnect/restart path.

## Checks

Run `bun test test` in this package after integration. These permanent tests cover canonical-response validation, scoped exclusion, coalescing, version deduplication, stale-fetch/session shutdown races, reconnect catch-up, private handle non-disclosure, initial model context, Eval-independent bootstrap, forks, compaction, context-boundary restoration, both extension registration orders, passive refresh and subscription cleanup. An isolated loopback HTTP fixture checks actual native SSE startup failure. These package tests do not start a model or database. The separate Trailboss suite uses the real OMP SDK with deterministic provider/tool gates to exercise idle non-waking and active-boundary freshness; it does not substitute for authenticated installed-session activation.
